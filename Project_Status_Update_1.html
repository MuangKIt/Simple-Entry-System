รายงานความคืบหน้าโครงงาน

กลุ่มที่ 2: ระบบจัดการคลังสินค้า (WMS Simple Entry System / Demand Forecasting System)

1. คำอธิบายโดยสังเขปเกี่ยวกับ Application ที่พัฒนา

WMS Simple Entry System คือระบบจัดการคลังสินค้าขนาดเล็กถึงขนาดกลาง ที่ออกแบบให้ใช้งานง่ายและรวดเร็ว รองรับการทำงานผ่านคอมพิวเตอร์และสมาร์ทโฟน โดยมีการแบ่งสิทธิ์การใช้งานเป็น 2 ระดับ:

  • Admin (ผู้ดูแลระบบ): มีสิทธิ์สูงสุด ควบคุมข้อมูลหลัก (Master Data), จัดการผู้ใช้งาน (User Management), ตั้งค่าจำนวนขั้นต่ำของสินค้า (Threshold Quantity) เพื่อเตือนเมื่อสินค้าใกล้หมด และดูรายงานเชิงบริหารของระบบ
  • Staff (พนักงานคลังสินค้า): มีหน้าที่บันทึกการรับสินค้าเข้า (Stock-In) และจ่ายสินค้าออก (Stock-Out) ผ่าน UI ที่ออกแบบมาสำหรับมือถือโดยเฉพาะ ระบบจะไม่อนุญาตให้ Staff แก้ไขข้อมูลหลัก หรือดูรายงานเชิงบริหาร

แนวทางการพัฒนา (Development Approaches): Hybrid (Plan-driven + Agile)

  • Plan-driven: ใช้กับส่วนที่แก้ไขทีหลังได้ยาก เช่น สถาปัตยกรรมระบบ (System Architecture) และโครงสร้างฐานข้อมูล (Database Schema)
  • Agile: แบ่งการทำงานเป็นรอบ (Sprint) สำหรับส่วนที่ขึ้นอยู่กับ Feedback เช่น การออกแบบ UI/UX และกระบวนการทำงาน เพื่อความยืดหยุ่น

2. ภาพรวมแผนงาน (Project Plan)

Sprint กิจกรรม (Activities) ผลลัพธ์ (Deliverables) ผู้รับผิดชอบ สถานะ
1 รวบรวม Requirement (RE Process), ออกแบบ ER Diagram/Database Schema และพัฒนาโครงสร้าง Core API เบื้องต้น พร้อมระบบ Authentication เอกสาร SRS, โครงสร้างฐานข้อมูลเบื้องต้น และระบบ Login สามารถใช้งานได้ ชยิน, รัฐพงษ์, ชิษณุพงศ์, กิตติภณ เสร็จสิ้น
2 พัฒนาระบบจัดการคลังสินค้าหลัก (Basic Inventory), ระบบตัดสต็อก (Simple Deduction) และพัฒนาหน้า UI สำหรับ Admin และ Staff ระบบติดตามระดับ SKU, บันทึกข้อมูลพื้นฐาน และแสดงผลบน UI ได้จริง กิตติภณ (Dev หลัก) เสร็จสิ้น
3 พัฒนาระบบแจ้งเตือนสินค้าใกล้หมด (Threshold Alert), พัฒนาระบบจัดการผู้ใช้งาน (User & Role Management) และ Dashboard สรุปผล แสดงแจ้งเตือน Low Stock และแบ่งสิทธิ์ Admin/Staff ได้สมบูรณ์ กิตติภณ (Dev หลัก) กำลังดำเนินการ
4 รวมระบบทั้งหมด ทดสอบภายในทีม (End-to-End Testing) และนำ Prototype ให้ทีม User ทดลองใช้งานเพื่อเก็บ Feedback ระบบพร้อมใช้งานจริงและส่งมอบรายงานสรุปโปรเจค สมาชิกกลุ่มทุกคน ยังไม่เริ่ม

3. ความคืบหน้าของโครงงาน (Progress Update)

ความคืบหน้าปัจจุบันคิดเป็น: ประมาณ 75% ของแผนงานทั้งหมด

สิ่งที่ทำไปแล้ว (Completed):

  • โครงสร้างและหน้าจอ UI ทั้งหมด (Admin Dashboard และ Staff Mobile UI)
  • สถาปัตยกรรมระบบหลังบ้าน (Node.js + Express) และ API แบบ RESTful ครบทุกฟังก์ชันหลัก
  • การเชื่อมต่อ Frontend กับ Backend ด้วย Fetch API แทนการใช้ข้อมูลจำลอง
  • ระบบรักษาความปลอดภัยเบื้องต้น (Authentication Guard) และการแบ่งสิทธิ์ (Role-based access)
  • ฟังก์ชันทำรายการหลัก (Stock-In และ Stock-Out) ที่ตัดสต็อกได้จริง

สิ่งที่เหลืออยู่ (To Do):

  • ปรับปรุงความสมบูรณ์ของฟีเจอร์รอง เช่น ระบบเปลี่ยนรหัสผ่าน การจัดการโปรไฟล์พนักงาน
  • ทดสอบการทำงานของระบบแจ้งเตือนสินค้าใกล้หมดให้ครอบคลุม
  • วางแผนย้ายฐานข้อมูลจากไฟล์ JSON ชั่วคราวไปใช้ Database จริง (Relational Database)
  • การทำ End-to-End Testing และ User Acceptance Test (UAT) ตาม Sprint ที่ 4

4. บันทึกการพัฒนา (Dev Log)

ขั้นตอนที่ได้ดำเนินการมา:

  • Phase 1 - Prototyping: เริ่มต้นออกแบบ User Interface โดยใช้งาน AI ช่วยสร้างหน้าจอทีละหน้า ได้ผลลัพธ์เป็น UI Prototype เปล่าๆ ที่แสดงผลข้อมูลจำลอง (Mock Data) และปุ่มคำสั่งต่างๆ ยังเป็นเพียง Dummy
  • Phase 2 - Backend & Architecture: นำโค้ด UI มาพัฒนาต่อในสภาพแวดล้อมที่ใช้งานได้จริง จัดโครงสร้างโฟลเดอร์ให้เป็นระเบียบ (แยก routes, controllers, middlewares) และพัฒนา REST API ด้วย Node.js และ Express โดยใช้ไฟล์ data.json เป็นฐานข้อมูลหลักชั่วคราว
  • Phase 3 - Integration: นำหน้าจอฝั่ง Frontend (ที่เคยฝัง Mock Data) มาเขียนคำสั่ง Fetch API เพื่อดึงข้อมูลจริงจาก Backend พร้อมทั้งสร้างระบบ Login ตรวจสอบสิทธิ์ก่อนเข้าใช้งานหน้าต่างๆ
  • Phase 4 - UX/UI Refinement: ปรับปรุงความสวยงามและประสบการณ์การใช้งาน เช่น
    • เพิ่มระบบจำลองเวลาโหลด (Loading Spinner) ก่อนยืนยันทำรายการ
    • เพิ่ม Success Modal แจ้งเตือนเมื่อทำรายการเสร็จ พร้อมแสดงเลขที่อ้างอิง (Ref-ID) และวันเวลา
    • ปรับโทนสีป้ายสถานะ (In Stock, Low Stock, Out of Stock) ให้เป็นโทนสีพาสเทล/ตุ่น เพื่อความสบายตา

ผลลัพธ์ปัจจุบัน:
ได้เป็น Prototype ที่สามารถรันใช้งานได้ใน Local Environment ระบบหลักสามารถทำงานได้อย่างสมบูรณ์ ข้อมูลมีการเชื่อมต่อกันจริง และสามารถนำสมาร์ทโฟนที่อยู่ในเครือข่ายเดียวกัน (Local Network) เปิดใช้งานหน้า Staff UI ได้ทันที

แผนการในอนาคต:
พัฒนาฟีเจอร์รองให้สมบูรณ์ครบถ้วน และพิจารณาปรับปรุงสถาปัตยกรรมข้อมูลไปใช้ Database ที่เป็นระบบจัดการฐานข้อมูลจริงๆ (เช่น MySQL, PostgreSQL) เพื่อเตรียมพร้อมสำหรับ Production
